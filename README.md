# EN Lesson Translator — локальный помощник на уроках английского

Десктопное приложение для Windows. Слушает системный звук (звонок/видео),
распознаёт **английскую и русскую речь**, дожидается окончания фразы и переводит
**EN → RU или RU → EN**. Язык определяется для каждой фразы автоматически.
История хранится локально.

Опциональный **ИИ-помощник через Ollama** учитывает предыдущие реплики,
может следовать **вашему промпту на каждой реплике** и отвечать на ручные вопросы
по сохранённому контексту. Старый режим вариантов ответа на EN/RU также доступен.
Распознавание, перевод и ИИ выполняются на вашем компьютере, без облачного API.
После загрузки моделей можно работать офлайн.

## Возможности

- Захват системного аудио (WASAPI loopback) — звук из звонка Zoom/Teams/Skype
  или видео в браузере, без виртуальных кабелей.
- VAD (детекция голосовой активности) на нейросети **Silero VAD**: перевод
  запускается только после того, как в речи возникла пауза ~1.5 сек — то есть
  после **окончания фразы**, а не после каждых 2-3 слов.
- Распознавание речи — `faster-whisper` (локальная модель Whisper).
- Перевод EN ↔ RU — `argostranslate` (два офлайн языковых пакета).
- Автоопределение языка каждой фразы через Whisper, без ручного переключения.
- ИИ через Ollama: **свой промпт** в интерфейсе, сохранение между запусками,
  содержание, язык EN/RU и задача задаются в промпте. Формат подсказок теперь
  фиксирован: **короткий + развёрнутый варианты**, английский — **не выше A2**.
- **Отдельный перевод ответов ИИ** через локальный Argos: английский ответ →
  русский перевод, русский ответ → английский. **Каждый вариант переводится
  отдельно.** Оригинал и перевод копируются
  разными кнопками, сохраняются и в истории фраз, и в ручном чате.
- Режим **«Обрабатывать каждую реплику по промпту»** (по умолчанию включён):
  ИИ отвечает и на утверждения, без классификации «вопрос / не вопрос».
  Для старых коротких EN/RU-подсказок снимите этот флажок.
- **Ручной контекстный чат** — можно задать вопрос даже при остановленном
  прослушивании и выключенных автоответах.
- Сохранённая память: до 200 событий (услышанная речь, ручные вопросы/ответы,
  примеры ИИ). Отдельные роли не выдают предложенные варианты за сказанное вами.
- Подсказки можно копировать отдельно на каждом языке; они сохраняются в истории.
- **Скриншот + вопрос в ИИ**: отдельный хоткей `Ctrl+Alt+S`, выбор области,
  предпросмотр и необязательный комментарий. Локальная `qwen3-vl:4b` понимает
  и текст, и изображения; распознавание речи и перевод продолжаются.
- Распознавание/перевод и ИИ работают в разных потоках. Перевод отображается
  до готовности подсказок. Ошибка Ollama не отключает перевод.
- Локальная история последних 50 фраз (SQLite), старые записи автоматически
  удаляются.
- Копирование перевода одним кликом (кнопка у текущей фразы и у каждой
  карточки истории).
- Контекст урока: лента предыдущих фраз + переводов + прикреплённых
  скриншотов.
- По желанию: исключение **основного окна** из системного захвата Windows
  (Windows 10 2004+ / Windows 11, с проверкой результата API; не гарантия для всех рекордеров).
- Снимок экрана по горячей клавише, автоматически прикрепляется к
  **следующей** распознанной фразе.

## Требования

- Windows 10/11, 64-бит.
- Python 3.10–3.13 (компилятор C++ не нужен — все зависимости ставятся
  готовыми колёсами).
- Рекомендуется минимум 4 ГБ свободной RAM и современный CPU
  (Whisper "small" на CPU; скорость зависит от длины фразы и процессора,
  универсальной гарантии «1–3 секунды» нет).
- **Дополнительно для ИИ:** установленная Ollama и RAM под выбранную модель.
  По умолчанию используется **`qwen3-vl:4b`** для текстовых подсказок и изображений.
  При совместной работе с Whisper, Argos и системой ориентируйтесь на **16 ГБ
  общей RAM или больше**; фактические требования зависят от квантования,
  размера картинки и настроек. Достаточная VRAM помогает скорости, на CPU разбор
  снимка может быть долгим. Это ориентиры, а не гарантии скорости/качества.
  Лёгкую текстовую модель можно выбрать через `LESSON_OLLAMA_MODEL`, но она
  не сможет разбирать изображения.


## Установка

```bash
cd english-lesson-translator
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### Разовая настройка моделей (нужен интернет один раз)

```bash
python scripts/setup_models.py
```

Это подготовит:
- детектор речи Silero VAD (модель ~1 МБ идёт прямо внутри pip-пакета
  `silero-vad`, скрипт только прогревает её — интернет для неё не нужен);
- модель Whisper (`small` по умолчанию, см. `app/config.py` →
  `WHISPER_MODEL_SIZE`, можно сменить на `tiny`/`base`/`medium`);
- оба офлайн языковых пакета Argos Translate en→ru и ru→en.
  Если раньше был установлен только en→ru, запустите скрипт повторно — он
  скачает только отсутствующий пакет.

После этого шага интернет не требуется — всё распознавание и перевод
работают локально.

## Подготовка перед уроком, задержки и локальная загрузка

1. При необходимости включите флажок ИИ (Ollama уже должна быть запущена).
2. Нажмите **«Подготовить модели до урока»**. Подготовка идёт в фоне; звук
   **не записывается**, этап виден в строке состояния. Первый запуск может
   занять десятки секунд: Silero, Whisper с пробным распознаванием тишины,
   оба направления Argos с первым проходом Stanza, затем Ollama без истории
   и без генерации. Пробные фразы не сохраняются в историю.
3. Дождитесь **«Модели готовы»**, затем начинайте прослушивание.
   При первом нажатии «Начать слушать» эта подготовка выполняется автоматически
   до открытия записи. Ошибка базовых моделей не разрешает начать запись;
   ошибка Ollama показывается отдельно и не запрещает обычный перевод.

Подготовка не делает вычисления бесплатными: длинная фраза, медленный CPU,
нехватка RAM и параллельная работа Ollama могут по-прежнему замедлять обработку.
Базовые модели готовятся один раз за запуск приложения. Ollama может выгрузить
модель после периода бездействия (`keep_alive=30m`); кнопка подготовки позволяет
прогреть её снова перед уроком. Если включили ИИ после подготовки, нажмите кнопку
ещё раз до начала записи. Ручной чат без подготовки тоже работает, но первый
запрос может ждать загрузку моделей.

Во время работы Whisper использует `local_files_only=True` и не проверяет
ревизию на Hugging Face. В `main.py` дополнительно включён offline-режим HF.
Silero использует pip-модель или локальный torch.hub-кеш; скачивание с GitHub
разрешается только явно скрипту `setup_models.py`. Для Argos принудительно выбран
локальный OPENNMT, а адаптер Stanza запрещает скачивание ресурсов
(`download_method=None`) и кеширует pipeline, включая старые версии Argos.
Если локальных ресурсов не хватает, подготовка выдаст ошибку вместо скачивания.
Онлайн-установка моделей остаётся отдельным шагом. Это настройки загрузчиков,
а не системный межсетевой экран. Используйте именно локальную модель Ollama,
не облачный вариант. HTTP к `127.0.0.1:11434` — связь с локальной Ollama.

Лог показывает время отдельных этапов подготовки и для каждой фразы:
`ASR=… перевод=… всего=… (без очереди/ИИ)`. Время ASR включает потребление
ленивого генератора Whisper. Метрики Ollama отдельно показывают `load`, `prompt`
и `generation`. Эти новые замеры не пишут текст разговора; подробный INFO-лог
Argos с текстами и токенами отключён (предупреждения остаются).

### Если ИИ выдумывает имя или происхождение

Даже мультимодальная модель 4B может уверенно ошибаться: перевод Argos лишь переводит её текст,
а не проверяет факты. В режиме двух вариантов, если вопрос о происхождении
**вашего** имени не содержит доступного приложению имени, код запрашивает
уточнение, не вызывая LLM для догадки. Показываются короткий и развёрнутый
варианты с отдельными переводами. Введите, например, `Артур имя` в ручном чате:
это связывается с предыдущим заданием. Можно записать `Меня зовут Артур.`
отдельным предложением в сохранённом промпте. Более новые ручные сведения
приоритетнее профиля; имена из старых ответов ИИ не считаются вашими фактами.
Это защита конкретного сценария, **не фактчекинг всех ответов/этимологий**.
Более крупная модель может быть качественнее, но требует больше памяти и тоже ошибается.

При обновлении ZIP сохраняйте свою папку `data/` и прежнюю `.venv` либо
обновляйте код в старой папке. Новая распакованная копия без прежней `data/`
не содержит старой истории и профиля. Для этих исправлений новых зависимостей
не добавлено.

## ИИ-подсказки: настройка Ollama (необязательно)

1. Установите **Ollama** с официального сайта `https://ollama.com` на тот же
   компьютер, где работает приложение. Запустите Ollama.
2. В терминале скачайте и предварительно прогрейте многоязычную модель:

   ```bash
   ollama pull qwen3-vl:4b
   ollama run qwen3-vl:4b
   ```

   После появления приглашения модели можно выйти командой `/bye`. Если сервер
   Ollama не запускается автоматически, запустите `ollama serve` в отдельном
   терминале. Скачивание модели требует интернета и нескольких ГБ на диске.
3. Запустите приложение и отметьте **«ИИ-подсказки по контексту»**. По умолчанию
   флажок выключен: обычный перевод не требует Ollama.

При стандартной инструкции, например: после «We are talking about hobbies» и «What do you do in your free time?»
перевод появится как обычно, а ИИ может предложить «I enjoy reading» / «Я люблю
читать» и «I usually go for a walk» / «Я обычно хожу на прогулку». Для русского
вопроса также будут показаны оба языка. Это **варианты для выбора**, а не
утверждения о ваших реальных интересах.

### Свой промпт и ручной вопрос по контексту

Откройте вкладку **«Промпт и чат»** справа:

1. Введите инструкцию (до 1500 символов) и нажмите **«Применить и сохранить промпт»**.
   Например:

   > Ты мой помощник на уроке. Меня зовут Алексей. Предлагай короткий ответ от
   > моего лица на английском и рядом русский перевод. Если обсуждается новое
   > слово, кратко объясняй его значение. Не выдумывай неизвестные личные факты.

   Или: «После каждой реплики кратко пересказывай по-русски, о чём идёт речь».
   Промпт задаёт содержание, язык основного ответа (EN/RU), объяснения и т. д.
   При этом формат подсказок фиксирован приложением: короткий и развёрнутый
   варианты, к каждому — отдельный перевод. Это действует и для ранее
   сохранённых промптов; переписывать старую инструкцию для этого не нужно.
2. Оставьте **«Обрабатывать каждую реплику по промпту, не только вопросы»**.
   Для автоматической обработки также включите **«ИИ-подсказки» слева** и
   прослушивание. При снятом флажке обработки каждой реплики возвращается
   старый режим: определение вопроса и два коротких двуязычных варианта;
   пользовательский промпт в нём — дополнительные пожелания, а не смена формата.
3. В поле ручного вопроса напишите, например, **«Что мы обсуждали?»** или
   **«Как ответить на последнюю просьбу преподавателя?»** и нажмите
   **«Спросить по контексту»**. В ручном режиме ИИ использует сохранённый промпт
   и фрагмент памяти. Включать захват звука или автоответы для этого не нужно.
   Следующий ручной вопрос учитывает предыдущий вопрос и ответ ИИ.

Промпт и режим сохраняются в `data/history.db`, в том числе при закрытии окна.
Новое сохранение применяется к следующим запросам; уже начатая генерация
завершится со старой инструкцией. Кнопка ручного вопроса также сохраняет
текущий текст промпта перед отправкой.

#### Два варианта и уровень A2

Для автоматических подсказок **и ручного чата** Ollama получает JSON-схему с
обязательными полями `short_answer`, `long_answer`, `answer_language`. Один
текстовый ответ больше не считается успешной выдачей двух вариантов:

- **Короткий вариант:** 1–2 простых предложения, ориентир 15–30 слов.
- **Развёрнутый вариант:** 3–5 простых предложений, ориентир 40–70 слов.
  Он должен добавлять конкретную полезную информацию, а не дублировать короткий.
- **Уровень английского — максимум A2:** обычные слова, простые времена и
  короткие предложения, без сложных идиом и академических слов. Например,
  вместо «its origin is uncertain/debated» — «People are not sure…».
  Неопределённость происхождения имени не должна заменять весь ответ: можно
  добавить известные связи с историями или известными людьми, не выдавая их
  за доказанную этимологию и не выдумывая семейные факты.
- Оба варианта создаются **за один запрос** Ollama. Каждый оригинал отдельно
  переводится Argos, затем отображается вместе со своим переводом.
- Если модель вернула один вариант, пустой, дубликат или «длинный» вариант
  короче короткого, показывается ошибка с предложением повторить запрос,
  а не незаметно выводится одна подсказка.

JSON-схема и проверка обеспечивают структуру двух вариантов, но A2 и полезность
содержания задаются инструкциями: формального лингвистического анализатора нет,
модель может ошибаться. Длины — ориентиры для генерации, не CEFR-сертификация.
Для старого режима «только вопросы» также задаётся A2 и требуются два варианта,
когда модель определила, что ответ нужен.

В карточках текущей фразы и истории есть отдельные блоки «Короткий вариант» и
«Развёрнутый вариант», под каждым — перевод и кнопки копирования. В ручном чате
они показаны в таком же порядке: короткий → его перевод → развёрнутый → его
перевод; общие кнопки копируют оба оригинала или оба перевода. Один вариант
также можно выделить мышью. Структура сохраняется между запусками; старые
одиночные ответы остаются в истории без автоматического дополнения.

#### Уточнения к предыдущему заданию

Короткое сообщение с личными сведениями теперь не рассматривается автоматически
как отдельный вопрос. Например:

- Услышано: **Tell me about the origin of your name.**
- Вы: **моё имя Артур**
- Приложение явно передаёт модели: **дополни предыдущее задание**, имя — Артур,
  подготовь готовый ответ от лица ученика, а не общий текст «происхождение имён
  бывает разным» и не просьбу снова назвать имя.

То же правило поддерживает явные уточнения вроде «меня зовут Анна»,
«My name is Alice», «Артур имя», «имя Артур», «я живу в Казани» после вопроса о месте жительства.
Новый самостоятельный вопрос (например, «Объясни Present Perfect») не подменяется
старым заданием. Это ограниченная эвристика, а не универсальный анализ намерений.
Уточнения и текст задания передаются также явно в конце запроса, а история
разговора — с настоящими ролями user/assistant. Факты из черновиков ИИ не
становятся фактами о пользователе; более свежие уточнения имеют приоритет.
Для происхождения имён модель может использовать общие знания, но должна
указывать неопределённость спорных этимологий и не выдумывать семейную историю.
Качество конкретного текста всё равно зависит от выбранной модели; тесты
проверяют сборку контекста и контракт ответа, а не знания настоящей Ollama.

#### Перевод подсказок и ручных ответов

Приложение получает два основных варианта на EN или RU с указанием языка, затем
**самостоятельно переводит каждый через Argos**, а не надеется на то, что модель
выполнит пожелание «добавь русский перевод» в промпте. При запросе двуязычного
ответа оба оригинала — английские; русский перевод каждого добавляется отдельно.
В текущей подсказке, карточках истории и ручном чате показываются **оба оригинала
и перевод каждого**, есть кнопки копирования. Перевод не дублируется в памяти
модели: в контекст попадает только оригинал, чтобы не расходовать окно дважды.

Нужны оба пакета Argos EN↔RU (`python scripts/setup_models.py`). Если переводчик
недоступен, исходный ответ не теряется: рядом показывается ошибка перевода.
Это не второй запрос к Ollama. Машинный перевод может быть неточным, проверяйте
термины и имена собственные. Старые записи БД сохраняются при миграции, но
ранее полученные ответы не переводятся задним числом — повторите запрос, если
для старого ответа нужен перевод.

#### Как устроена память

- Память ИИ — отдельная таблица в той же SQLite-БД, **не лента последних
  50 переводов**. Она хранит до **200 последних событий** между запусками.
  При первом обновлении в неё однократно копируются существующие переводы
  (только исходные распознанные фразы).
- Услышанные фразы добавляются даже при выключенных автоответах, если идёт
  распознавание. Ручные вопросы и ответы также сохраняются; неудавшийся запрос
  сохраняет вопрос, но не выдумывает ответ.
- В модель передаётся не вся память: **приоритетный фрагмент до 3000 символов**.
  Сначала резервируется место под актуальную услышанную задачу и последнее
  явное уточнение пользователя, затем — под свежую речь и ручные сообщения.
  Их длина ограничена 800 символами; из старых ответов/подсказок берутся только
  два последних фрагмента до 240 символов, чтобы повторы ИИ не вытесняли задачу.
  Этот фрагмент виден над чатом. Это не
  бесконечная память и не поиск по всему уроку: старые сведения могут не попасть
  в окно; модель должна прямо говорить, если данных недостаточно.
- **«Очистить память и чат»** начинает новый контекст, не удаляя промпт и
  историю переводов. Очистка не подтягивает старую историю заново после
  перезапуска. Ещё не начатые автоответы по старой памяти пропускаются;
  уже идущий запрос нельзя мгновенно остановить, но его устаревший результат
  не восстанавливает очищенную память.
- Ручной запрос выполняется в фоне. Запросы к одной модели сериализованы:
  если идёт автоответ, чат может подождать его завершения. Перевод не блокируется.
  Остановка прослушивания не закрывает ручной чат.
- «Каждая реплика» означает отсутствие фильтра по вопросу, **не гарантию успеть
  за любым темпом речи**: в реальном времени сохраняется один ожидающий
  автозапрос и один выполняющийся; при перегрузке старый ожидающий запрос
  пропускается с явным статусом, но услышанные фразы остаются в памяти.
- Лимиты памяти, длины промпта и вопроса задаются в `app/assistant_workspace.py`.
  Слишком большой контекст и длинные ответы увеличивают задержку. У обычных
  подсказок бюджет 384 токена, у автоответа по промпту 512, у ручного ответа 768;
  при обрезанном ответе показывается ошибка, а не пустая подсказка.

### Настройки ИИ

Адрес по умолчанию — `http://127.0.0.1:11434`, модель — `qwen3-vl:4b` (текст + изображения).
Можно выбрать другую локальную модель через переменные окружения **до запуска**.
Например, в PowerShell:

```powershell
ollama pull qwen3-vl:4b
$env:LESSON_OLLAMA_MODEL = "qwen3-vl:4b"
python main.py
```

`LESSON_OLLAMA_URL` позволяет сменить локальный порт (например,
`http://127.0.0.1:11435`). В целях приватности разрешены только HTTP-адреса
`localhost`, `127.0.0.1` и `::1`; облачные и LAN-адреса не принимаются.
В `app/config.py` настраиваются `ASSISTANT_TIMEOUT_SECONDS` (по умолчанию 60 с),
`ASSISTANT_VISION_TIMEOUT_SECONDS` (180 с для снимков/прогрева),
`ASSISTANT_CONTEXT_ENTRIES` (4) и ограничение длины текста (800 символов на
реплику) для старого режима подсказок. Предыдущие реплики передаются только в оригинале, без дублирования
переводом; текущая фраза — с переводом.
Если модель не успевает ответить, попробуйте меньшую модель, прогрев через
`ollama run` или увеличьте таймаут. Ошибка и подсказка по настройке появятся под
переводом. Распознавание и перевод при этом продолжаются.

### Как ускорить подсказки

Текстовые подсказки, ручной чат и снимки используют одну выбранную модель
(по умолчанию `qwen3-vl:4b`) и общее окно 8192 токена. Оно больше прежнего 4096,
чтобы оставалось место для изображения и текста; это увеличивает расход памяти.
Бюджеты генерации: старые подсказки 384 токена, автоответ по промпту 512,
ручной чат 768, разбор снимка 1800. Увеличение бюджета не гарантирует
достоверности; обрезанный ответ показывается как ошибка.
Модель остаётся загруженной 30 минут между запросами (`keep_alive`), чтобы не
загружать её заново после коротких перерывов. Это занимает RAM/VRAM;
после урока: `ollama stop qwen3-vl:4b`.

Старая скачанная модель не заменяется автоматически. Скачайте новую явно:
`ollama pull qwen3-vl:4b`, обновите Ollama при необходимости, затем установите
`LESSON_OLLAMA_MODEL` как в примере выше и перезапустите приложение. Если эта
переменная указывает на старую `qwen2.5:3b`, она имеет приоритет над новым
значением по умолчанию: текст продолжит работать, снимки — нет.

- **Долго ждёте до появления перевода?** Это ещё не Ollama: тратится время на
  VAD, Whisper и Argos. Для слабого CPU можно попробовать `WHISPER_MODEL_SIZE =
  "base"` в `app/config.py`, затем повторить `python scripts/setup_models.py`.
  Это быстрее не на любом ПК и может ухудшить распознавание. Не используйте
  `base.en`: нужна поддержка русского.
- **Перевод уже есть, подсказки долго нет?** Проверьте `ollama ps` во время
  генерации: колонка PROCESSOR показывает использование CPU/GPU. Если доступная
  GPU не используется, проверьте поддержку видеокарты Ollama и драйверы.
  На CPU генерация VL-модели тоже может быть медленной. Whisper и Ollama делят ресурсы.
- **Только первый ответ медленный?** Заранее прогрейте модель через `ollama run
  qwen3-vl:4b` (после приглашения введите `/bye`).
- В консоли приложения теперь есть строки `Ollama model=… wall=… load=…
  prompt=… generation=…`: время запроса, загрузки, обработки контекста и
  генерации в секундах. Текст разговора в эти метрики не записывается.
- «Вопрос не обнаружен», «Пропущено…» и «Подсказки недоступны…» — разные
  ситуации: классификация, очередь и ошибка/таймаут соответственно.
  Ответ на предыдущую фразу ищите в её карточке истории.

### Ограничения

- В старом режиме подсказок ИИ вызывается при включённом флажке. Для явных просьб
  «Tell me…», «Explain…», «Describe…», «Расскажи…», «Объясни…» приложение
  дополнительно требует два ответа через JSON-схему, даже если нет `?`.
  Например, «Tell me the origin of your name.» — это просьба ответить, а не
  обычное утверждение. Без личных данных модель должна дать шаблон для
  заполнения либо ответ о том, что происхождение имени вам неизвестно, а не
  придумывать этимологию. Для остальных реплик решение принимает модель.
  Правила не охватывают все формулировки, модель всё ещё может ошибаться.
- В контекст попадают последние сохранённые реплики, в том числе из предыдущего
  запуска; это ограниченное окно, а не память всего урока. Подсказки из истории
  не выдаются за реально произнесённые вами ответы.
- Сохраняется максимум один ожидающий запрос ИИ плюс один выполняющийся.
  Если речь идёт быстрее генерации, устаревшие ожидающие запросы пропускаются
  в пользу новой фразы. При этом ожидающий явный вопрос/просьба имеет приоритет:
  в старом режиме обычное утверждение не вытесняет его из очереди. Из двух вопросов выбирается
  более новый. Это простая эвристика (просьбы и `?`), не полное понимание смысла.
  Переводы и история фраз при этом не пропускаются.
- Отключение флажка отменяет ещё не начатые запросы; уже выполняющийся локальный
  запрос может завершиться. При остановке прослушивания результат ИИ уже не
  показывается. Если обработка ещё завершается, повторный старт нужно немного
  подождать (до таймаута запроса).
- На коротких фразах и смешанной EN/RU-речи Whisper может неверно определить
  язык. Нужна **многоязычная** модель Whisper (`small`, а не `small.en`).
  Другие языки пока не поддерживаются; ошибка будет показана в строке состояния.
- Приложение слушает **системный выход**, не микрофон. RU → EN работает для
  русской речи в этом аудиопотоке. Захват собственного микрофона не добавлен.
- Обычная речь и ручной чат передают только текст. Изображение видит только
  зрительная модель в отдельном режиме после подтверждения отправки. Снимки
  для истории (`Ctrl+Shift+S`) не отправляются в ИИ. Подсказки не озвучиваются
  и не отправляются в звонок.

## Запуск

```bash
python main.py
```

Для глобальных горячих клавиш (библиотека `keyboard`) на Windows может
потребоваться запуск от имени администратора.

## Пауза перед распознаванием — 1,5 секунды

`END_OF_SPEECH_SILENCE_MS = 1500` в `app/config.py` (раньше было 700 мс).
Silero обрабатывает окна по 32 мс, поэтому порог округляется **вверх** до
47 окон: **1504 мс**, а не вниз до 1472 мс. Возобновление речи до порога
сбрасывает отсчёт тишины и продолжает ту же фразу. Это время ожидания окончания
речи, **не полная задержка ответа**: затем ещё идут Whisper, перевод и Ollama.
Защита `MAX_UTTERANCE_MS = 18000` по-прежнему может разбить очень длинную речь
даже без паузы.

## Исключение окна из демонстрации экрана (Windows)

Слева, под переключателем ИИ, добавлен флажок
**«Исключить основное окно из захвата экрана (Windows)»**.

1. Запустите приложение на **Windows 10 version 2004, сборка 19041 или новее**
   либо Windows 11. На других ОС/старых сборках флажок недоступен.
2. Включите режим **до демонстрации**. Локально окно остаётся видимым и
   доступным для чтения перевода; режим выключается тем же флажком.
3. Прочитайте статус под флажком: приложение вызывает
   `SetWindowDisplayAffinity(HWND, WDA_EXCLUDEFROMCAPTURE)` и проверяет результат
   через `GetWindowDisplayAffinity`. При ошибке показывается предупреждение,
   а не обещание невидимости. При пересоздании HWND/повторном показе Qt-окна
   включённый режим применяется повторно.
4. **Сделайте тестовую запись или проверьте демонстрацию со второго устройства**
   именно в вашей программе и выбранном режиме показа. Успех Windows API —
   не доказательство результата в Zoom/Teams/OBS/браузере.

В приложенном пользователем примере Electron использовался
`mainWindow.setContentProtection(true)`. Для нашего приложения на PySide6
добавлена собственная реализация через стандартный Windows API, без Electron
и новых библиотек. Посторонний код из примера не запускается и не включается
в приложение.

### Ограничения режима

- Это **исключение одного собственного основного окна из поддерживаемых
  механизмов системного захвата**, а не универсальная «невидимость программы».
  Конкретный рекордер/драйвер/режим захвата может игнорировать ограничение,
  показать пустую область или вести себя иначе. Камера, снимающая монитор,
  аппаратный захват и некоторые способы удалённого доступа не защищены.
- **Системные окна, панель задач, значок приложения, Alt+Tab и другие диалоги
  не скрываются.** Новые окна выбора/предпросмотра снимка защищаются отдельно
  при включённом флажке; к произвольным окнам это не относится. Не открывайте чувствительные диалоги во время показа.
  В сомнительных случаях надёжнее демонстрировать только другое конкретное
  окно, а не весь рабочий стол.
- На старых Windows не используется запасной режим `WDA_MONITOR` с чёрным
  прямоугольником: он не равнозначен исключению из захвата.
- Режим **по умолчанию выключен и не сохраняется между запусками**: включайте
  его явно перед показом и проверяйте результат. Изменение не влияет на
  микрофон, системное аудио, перевод или отправку текста в локальную Ollama.
- Это не средство DRM или защиты от всех способов копирования. При ошибке API
  или неподтверждённом состоянии не считайте окно защищённым.

## Снимок + вопрос, одновременно с речью

Это дополнительный режим, **не замена** распознаванию речи, переводу или
контекстным подсказкам. Whisper распознаёт звук, Argos переводит EN↔RU,
а Qwen отвечает на текст и изображения.

1. Откройте нужное окно (браузер, упражнение, рисунок, сообщение об ошибке).
   Поставьте курсор на нужный монитор и нажмите **`Ctrl+Alt+S`**. Также есть
   кнопка **«Снимок + вопрос ИИ»** во вкладке «Промпт и чат».
2. Выделите область мышью. Выбирается один монитор под курсором; область
   не пересекает мониторы. `Esc` или правая кнопка — отмена.
3. Проверьте снимок в предпросмотре, при необходимости допишите просьбу
   (до 1000 символов): «реши упражнение 3», «что здесь написано», «помоги
   ответить», «объясни ошибку». Пустой комментарий тоже допустим:
   модель попросим объяснить изображение, а при наличии задания — выполнить его.
4. Нажмите **«Отправить в локальную модель»**. Только теперь снимок сохраняется
   на диск и вместе с текстом, промптом и свежим контекстом отправляется в
   локальную Ollama. Отмена на любом этапе не сохраняет и не отправляет снимок.
5. Разбор появляется в ручном чате: объяснение/решение по-русски; если нужен
   английский ответ — короткий и развёрнутый варианты не выше A2, у каждого
   отдельный русский перевод через Argos. Полное решение упражнения остаётся
   в объяснении, а не заменяется двумя примерами. Модель может ошибаться;
   нечитаемый текст нужно снять крупнее, а не принимать догадку за факт.

Прослушивание **не останавливается**. Автоответы ИИ включаются прежним флажком;
ручной разбор работает и при выключенных автоответах, и без прослушивания.
Вычисления одной Qwen сериализованы: текущий автоответ может задержать разбор
снимка, а долгий разбор — следующую подсказку ИИ. Распознавание/обычный перевод
имеют отдельный рабочий поток, но конкуренция за CPU/RAM/GPU всё равно влияет
на скорость. Одновременно допустим один ручной запрос (текст **или** снимок).

Для ограничения нагрузки большая область уменьшается до 2048 пикселей по
длинной стороне **до предпросмотра**; есть предупреждение и просмотр 1:1 со
скроллом. Если текст мелкий, отмените и выберите меньшую область. PNG ограничен
8 МБ. В модель уходит только выделенная область, без оверлея выбора и без
оставшейся части рабочего стола. Старые изображения автоматически не
пересылаются: последующие текстовые вопросы используют текстовый контекст;
если нужны детали картинки, отправьте нужную область снова.

Подтверждённые снимки лежат в `data/screenshots/vision_*.png`, путь и разбор
сохраняются в локальном чате. Очистка чата **не удаляет файлы снимков**. Старый
`Ctrl+Shift+S` по-прежнему делает общий снимок для истории следующей фразы:
**он не отправляет его в ИИ**. Хоткеи настраиваются в `app/config.py`; новый
хоткей обрабатывается после отпускания клавиш и подавляется в активном окне.

При включённом исключении основного окна из захвата оно дополнительно
применяется к новым окнам выбора области и предпросмотра. Если Windows API
не подтверждает его применение, окно снимка не открывается и показывается
ошибка. Это всё ещё не гарантия для всех программ захвата; другие системные
окна, панель задач и произвольные диалоги не защищены автоматически.

## Горячие клавиши (настраиваются в `app/config.py`)

| Клавиши          | Действие                                              |
|------------------|--------------------------------------------------------|
| `Ctrl+Alt+S`     | Выбрать область → предпросмотр + текст → отправить в локальную Qwen |
| `Ctrl+Shift+S`   | Сделать снимок экрана, прикрепить к следующей фразе (не отправлять в ИИ) |
| `Ctrl+Shift+L`   | Старт/стоп прослушивания                                |

## Как работает определение "конец фразы"

1. Системный звук нарезается на окна по 32 мс (ровно 512 сэмплов при 16 кГц —
   Silero VAD принимает только такой размер окна).
2. Каждое окно переводится в `float32`-тензор и прогоняется через нейросеть
   **Silero VAD**, которая возвращает вероятность речи от 0.0 до 1.0.
3. Порог с гистерезисом: чтобы начать фразу, нужна уверенная речь
   (`VAD_THRESHOLD = 0.5`); пока фраза идёт, тишиной считается падение
   вероятности ниже `VAD_NEG_THRESHOLD = 0.35`. Так фраза не рвётся на тихих
   словах и согласных.
4. Пока идёт речь — окна копятся в буфере текущей фразы.
5. Короткие паузы (вдохи, < 1500 мс по умолчанию) не прерывают фразу.
6. Как только тишина продержалась не менее 1500 мс подряд — фраза считается
   законченной и целиком отправляется на распознавание+перевод.
7. Короткие случайные шумы (< 400 мс речи) отбрасываются — это не фразы.
8. Если человек говорит очень долго без пауз (> 18 сек) — фраза форсированно
   разбивается, чтобы не копить гигантский буфер.
9. Silero — рекуррентная модель (внутри LSTM), поэтому после каждой
   завершённой фразы вызывается `model.reset_states()`: предыдущая фраза не
   влияет на следующую.

Параметры (`VAD_THRESHOLD`, `VAD_NEG_THRESHOLD`, `END_OF_SPEECH_SILENCE_MS`,
`MIN_UTTERANCE_MS`, `MAX_UTTERANCE_MS`) настраиваются в `app/config.py`.

### Почему Silero VAD, а не webrtcvad

| | `webrtcvad` (было) | **Silero VAD** (стало) |
|---|---|---|
| Установка | C-расширение, нужен компилятор, нет колёс для Python 3.11+ | обычный pip-пакет (`pip install silero-vad torch`) |
| Поддержка | библиотека заброшена | активно развивается |
| Алгоритм | энергетический детектор, бинарный ответ | нейросеть, вероятность речи 0.0–1.0 |
| Качество | путает шум, музыку, щелчки с речью | устойчив к шуму, обучен на 100+ языках |
| Скорость | очень быстро | ~1 мс на окно 32 мс (одно ядро CPU) |
| Размер окна | 10/20/30 мс | строго 512 сэмплов (32 мс) при 16 кГц |

Модель загружается в `app/vad_segmenter.py` функцией `load_silero_model()`:
сначала из pip-пакета `silero-vad` (модель лежит внутри пакета — полностью
офлайн), при его отсутствии — из кеша `torch.hub` в `data/models/torch_hub`,
и только в крайнем случае скачивается с GitHub.

Хотите ONNX-версию вместо JIT (чуть быстрее на слабых CPU)? Поставьте
`onnxruntime` и выставьте `VAD_USE_ONNX = True` в `app/config.py`.

## Тесты

```bash
python -m unittest discover -s tests
```

Новые тесты клиента Ollama, истории, направлений перевода и пайплайна
используют заглушки и не требуют запущенной Ollama или загруженных ML-моделей.
Отдельно проверяются сохранение промпта и памяти, ручной чат, ошибки и очистка
контекста во время генерации. Есть проверки автоязыка Whisper и offscreen-проверки Qt-интерфейса (для них
нужны numpy и PySide6 с системными библиотеками Qt).

Тесты сегментатора используют заглушку вместо настоящей нейросети, поэтому
проходят за доли секунды и не требуют интернета. Отдельный тест проверяет и
настоящую модель Silero, если пакет `silero-vad` установлен.

## Приватность

Аудио обрабатывается локально в памяти; распознанный текст, перевод, подсказки,
пользовательский промпт, настройки, память ИИ, ручной чат с переводами и скриншоты сохраняются
локально в папке `data/`. ИИ получает по локальному HTTP сохранённый промпт,
текущую фразу/ручной вопрос и ограниченный фрагмент текстовой памяти. В старом
режиме это текущая фраза с переводом и последние 4 исходных реплики.
Запрос идёт в Ollama **на этом же компьютере**, без системного HTTP-прокси.
Аудио в Ollama не передаётся. Снимок отправляется только после явного
подтверждения в новом режиме «Снимок + вопрос ИИ»; обычная речь и чат
не пересылают сохранённые изображения. Используйте локальные модели Ollama,
а не облачные. При выключенных автоответах запросы всё равно возможны по
**явному нажатию кнопки ручного чата или отправке подтверждённого снимка**. Загрузка моделей и пакетов при разовой
настройке требует интернета. Старая SQLite-история обновляется без удаления
записей (для старых фраз подразумевается EN → RU). Очистка памяти ИИ не удаляет
историю переводов и скриншоты; она не является удалением всех локальных данных.
